# Proof registry — *The Zwegers shadow as U(1)-projected intrinsic torsion*

Machine-checked certificates, in [Lean 4](https://lean-lang.org) with
[Mathlib](https://github.com/leanprover-community/mathlib4), for the algebraic
and arithmetic content of

**The Zwegers shadow as U(1)-projected intrinsic torsion**
D. J. Master
Preprint DOI: [10.5281/zenodo.21772012](https://doi.org/10.5281/zenodo.21772012)

Sixteen certificates correspond to forty-seven numbered results of that paper.

## Contents

| Document | Contents |
|---|---|
| `Zwegers_Shadow_Paper_Lean_Correspondence.md` | Which paper result each certificate proves, and under which Lean declaration |
| `Zwegers_Shadow_Paper_Axiom_Audit.md` | The axiom footprint of every certified result, generated by `#print axioms` during the build |

The remaining sixteen files are the certificates themselves. Each states its own
scope in its header.

## What these certificates establish

Each certificate machine-checks the algebraic or arithmetic core of a result.
The geometric identification that gives that core its meaning — that a
particular algebraic object *is* the shadow, the torsion class, or the Dirac
spectrum of the geometry concerned — is established in the paper by ordinary
mathematical argument, and enters the certificate as a declared input rather
than as a conclusion.

The intent is that these certificates eliminate arithmetic and algebraic error.
They do not replace the geometric argument, and are not offered as doing so.

## Verification status

No certificate contains `sorry`, and none introduces an axiom of its own. Every
audited declaration depends on at most Lean's three foundational axioms
(`propext`, `Classical.choice`, `Quot.sound`); three depend on none. Per-result
figures are in the axiom audit.

## Toolchain and reproduction

Lean `4.29.1`, Mathlib pinned at `v4.29.1`.

Every file here imports Mathlib and nothing else — no certificate depends on any
other file in this directory or on any other part of the repository from which
these files are taken. They therefore compile independently, given Mathlib at
the pinned revision.

To reproduce the build, install [`elan`](https://github.com/leanprover/elan) and
build from the repository, which carries the `lean-toolchain` and
`lake-manifest.json` that fix the exact versions:

```bash
git clone https://github.com/shalome-ai/MEF_Proof.git
cd MEF_Proof
lake exe cache get     # fetch prebuilt Mathlib; skip and it will compile from source
lake build
```

Continuous integration runs the same build on every commit.
