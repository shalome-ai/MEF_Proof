# MEF_Proof — machine-checked certificates

Formal verification, in [Lean 4](https://lean-lang.org) with
[Mathlib](https://github.com/leanprover-community/mathlib4), of the algebraic
and arithmetic content of a series of papers in geometry and mathematical
physics.

## The paper

**The Zwegers shadow as U(1)-projected intrinsic torsion**
D. J. Master
DOI: [10.5281/zenodo.21772012](https://doi.org/10.5281/zenodo.21772012)

Sixteen certificates in `MEFProof/Paper_3/` correspond to forty-seven numbered
results of that paper. The mapping is tabulated in
[`Zwegers_Shadow_Paper_Lean_Correspondence.md`](MEFProof/Paper_3/Zwegers_Shadow_Paper_Lean_Correspondence.md).

## Verifying this yourself

Install [`elan`](https://github.com/leanprover/elan), then:

```bash
git clone https://github.com/shalome-ai/MEF_Proof.git
cd MEF_Proof
lake exe cache get     # fetch prebuilt Mathlib; skip and it will compile from source
lake build
```

`lake build` compiles every certificate in the repository. The library root
`MEFProof.lean` imports all of them, so a successful build is a verification of
the whole collection, not a subset. The first run downloads several gigabytes of
Mathlib and takes some minutes; subsequent runs are fast.

Continuous integration runs the same build on every commit — see the Actions
tab for the current status.

## What these certificates establish

Each certificate machine-checks the algebraic or arithmetic core of a result.
The geometric identification that gives that core its meaning — that a
particular algebraic object *is* the shadow, the torsion class, or the Dirac
spectrum of the geometry concerned — is established in the paper by ordinary
mathematical argument, and enters the certificate as a declared input rather
than as a conclusion.

Each file states its own scope in its header. The intent is that these
certificates eliminate arithmetic and algebraic error; they do not replace the
geometric argument, and are not offered as doing so.

## Toolchain

Lean `4.29.1`, Mathlib pinned at `v4.29.1`. Exact versions are fixed by
`lean-toolchain` and `lake-manifest.json`, so the build is reproducible.

No certificate contains `sorry`, and none introduces an axiom beyond Lean's
three foundational ones. See [`Zwegers_Shadow_Paper_Axiom_Audit.md`](MEFProof/Paper_3/Zwegers_Shadow_Paper_Axiom_Audit.md).
